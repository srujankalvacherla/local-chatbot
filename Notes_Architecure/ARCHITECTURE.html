Phase 3: LangChain-Powered LLM Module

📋 Project Overview

Local Chatbot is a Python-based conversational AI application that runs on your local machine using Ollama. It provides multiple interfaces (Streamlit web UI and terminal) powered by a unified LangChain-based chat engine.

Key Characteristic: This is Phase 3, which introduces LangChain for better abstraction, automatic memory management, and cleaner separation between UI and LLM logic.
Project Structure:

Component Breakdown

📦 chat.py (Core)

The heart of the application. Contains:

  • chat_once() - Single message handler
  • clear_memory() - Reset conversation
  • get_memory_messages() - Retrieve history
  • get_model() - Return model name

🌐 app.py (Web UI)

Streamlit-based web interface:

  • Chat message display
  • User input handling
  • Settings sidebar (temperature)
  • Memory visualization

⌨️ terminal.py (CLI)

Terminal interface using Rich:

  • Command-line chat
  • Commands: /history, /clear, /quit
  • Colored output
  • Shared memory with web UI

🔄 Data Flow

User Message Flow (Step-by-Step)

1

User Submits Message

Location: app.py (Streamlit) or terminal.py (CLI)

User types a message and hits send/enter. The UI captures the input string.

2

Chat Function Called

Location: chat.py → chat_once()

The UI calls chat_once(user_input) which returns a generator that yields response tokens.

3

Memory Injection

Location: chat.py → ConversationBufferMemory

LLMChain automatically retrieves previous messages from ConversationBufferMemory and injects them into the prompt.

4

Prompt Construction

Location: chat.py → ChatPromptTemplate

Template formats: [System Prompt] + [Chat History] + [User Message] into a structured prompt.

5

Send to Ollama

Location: chat.py → ChatOllama → http://localhost:11434

LLMChain sends the formatted prompt to ChatOllama, which connects to the local Ollama server.

6

LLM Processes & Streams

Location: Ollama Server (External)

Ollama runs the LLM (e.g., phi3) and streams response tokens back via HTTP.

7

Yield Tokens to UI

Location: chat.py → chat_once() generator

Tokens are yielded one-by-one for real-time display. The UI renders them as they arrive.

8

Store in Memory

Location: chat.py → ConversationBufferMemory

Once the response is complete, LLMChain automatically saves both user message and assistant response to memory.

9

Display in Chat

Location: app.py / terminal.py

UI fetches memory messages via get_memory_messages() and displays the full conversation.

✨ Key Features & Design Decisions

🔌 Pluggable UI

Both Streamlit and terminal interfaces share the same chat.py module. Users can run both simultaneously and share conversation history.

🧠 Automatic Memory Management

ConversationBufferMemory automatically stores and retrieves conversation history. No manual list management needed.

⚡ Real-Time Streaming

Response tokens stream in real-time from Ollama. Users see text appear character-by-character instead of waiting for full responses.

📦 Clean Separation

UI logic is isolated from LLM logic. Changes to chat.py (LangChain integration) require minimal changes to app.py.

🚀 Local-First

Everything runs locally. Ollama provides the LLM, no cloud API calls, full privacy.

🎛️ Configurable

Model, temperature, system prompt, and Ollama URL all configurable via environment variables.

🚀 Execution Paths

Running the Web UI

streamlit run app.py # What happens: # 1. Streamlit loads app.py # 2. Imports chat.py and builds LLMChain (once) # 3. Renders Streamlit UI # 4. User types → calls chat_once() → displays tokens # 5. Memory persists across reruns (Streamlit sessions)

Running the Terminal UI

python terminal.py # What happens: # 1. Loads chat.py (same module as web UI) # 2. Displays welcome banner # 3. Infinite loop: read user input → chat_once() → stream response # 4. Commands: /history, /clear, /quit # 5. Memory persists across messages (within same terminal session)

Running Both Simultaneously

# Terminal 1: streamlit run app.py # Starts at http://localhost:8501 # Terminal 2: python terminal.py # Run terminal UI # Result: # - Both share the SAME chat.py module # - Both share the SAME memory instance # - Send message in web UI → appears in terminal and vice-versa
